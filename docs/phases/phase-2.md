## Learned
- 2026-10-15 (A1 to A6): Every milestone went through the background security review, which found real problems each time, all fixed before moving on: goal ids were guessable and followed by name (now 12 random bytes); Memory and Agents counted as the owner's shell by program name (now only windows the broker started, checked through windows.check); an AI's memory could replace the owner's accountant (now a suggestion); a normalisation difference let odd groups slip past that check; conversation threads could be joined by anyone; window focus could be stolen while the owner typed a password (now refused while a SIOS window or a password prompt is in front); the reminder 'cancel' argument was reachable (now undo-only); a paused or removed agent kept its passes, waiting requests and memory shares; the agent sandbox bound the project's .git read-write (a planted hook would run outside: agents now work in their own clone) and the socket folder read-write (a fake capd.sock: now read-only); links on the workspace path, hooks in 'Make it a git project', and terminal escape codes in the live log. User units honour ProtectHome=tmpfs, BindPaths, BindReadOnlyPaths, LoadCredential and PrivateTmp on the VM (user namespaces): the sandbox hides /run/user too, so SIOS's socket folder is bound read-only on purpose; connecting to a socket on a read-only bind works, removing or creating one fails. systemd-run keeps % in commands as written but expands $ ($$ is a plain $). Plasma applies Do Not Disturb live from plasmanotifyrc with kwriteconfig6 --notify. KWin scripts answer through callDBus to capd's own zbus endpoint; workspace.createDesktop and window.desktops place an agent's terminal on its own desk. Claude Code 2.1.300 (official installer, ~/.local/share/claude/versions) runs headless in the sandbox with stream-json; until the agent signs in it answers 'Not logged in'. memsim: facts first, past tasks only when nothing else answers, and supersede by subject took it from 5 of 6 checks failing to every check passing every week.
- 2026-10-14 (owner, first image with M2 to M8): saving a key in Settings > Brain gave "only the owner can do that, from SIOS's own windows". Cause: Settings and Approve hid their memory (`PR_SET_DUMPABLE 0`), which also makes `/proc/<pid>/exe` unreadable to the same user, so the broker saw no program at all. Removed; the image pins `ptrace_scope=1` (this image already had it). The security review then showed an AI could start the window as its own child and attach to it, with or without the hiding; the fix (the broker starts its own windows) goes into S1. Also cleaned the VM: test copies moved to `~/sios-test-backup`, services now run `/usr/bin/capd` and `/usr/bin/brain-d`.
- 2026-10-14 (M2): The image build sent the whole repo to podman (1.7 GB of `target/` and `node_modules`, and `cosign.key`). A `.dockerignore` brings that to 428 KB. The `rust` stage on Fedora 44 compiles and tests both crates in about 25 seconds. `apps/build-rust.sh` is the fast loop: it builds for arm64 in Docker, runs the tests, and copies to the VM's `~/.local/bin`.
- 2026-10-14 (VM): The test VM is VMware Fusion, not UTM: `rohan@192.168.99.134`. Its network must be "Share with my Mac"; bridged to the Mac's Wi-Fi it never got an address. `sudo` there needs the owner's password, so image upgrades are the owner's step.
- 2026-10-14 (M3): Both services run on the VM from `~/.local/bin`. The state folder is 0700 and the files 0600; the sockets are in `/run/user/1000/sios` (0700/0600). With `SIOS_IDENTITY=peer`, a terminal that can read `owner.secret` gets "only the owner" for approve, pending and mint, and a hand-made `request_pass` carrying `service.secret` is refused. The new tests found one place (`request_pass`) that still checked the secret file directly; fixed. Identity is a runtime setting in the unit, not a build feature as D32 first said, so the image runs the tested binary. A user service gets the active session's NetworkManager rights (Wi-Fi power, network control: yes, no prompt) and the session's Wayland and D-Bus settings, so M6 adapters can run inside the broker. Hidden folders are now refused for every AI (except `.Trash`); a state folder in a hidden folder of the root is allowed. Not yet seen: the positive side (brain-d in `/usr/bin` recognised as the service, services starting after a reboot), which needs an image with M3. New risk: AT-SPI can press buttons in owner windows (12-risks, for M5).
- 2026-10-14 (M3, security review): Knowing callers by their program can be faked by a process of the same user: open the socket, keep a copy of the connection (fork or dup), then exec a trusted program in the child (after moving it into `sios-brain.service` for the service). The kernel then names the trusted program. So the owner is never proven by program now (`OWNER_BY_PROGRAM = false` in both crates). The service is re-checked before every request, and the loader-variable check covers whole families (`LD_*`, `QT_*`, `QML*`, `GCONV_PATH`...). M4's key saving and M5's approvals need a real owner anchor first: a decision for the owner.
- 2026-10-14 (D39): Owner chose a password prompt. Checked on the VM: a process in a user service asking polkit with interaction allowed (`pkcheck ... --allow-user-interaction`, action `org.kde.kcontrol.kcmkwallet5.save`, which needs your own password) makes KDE's "Authentication Required" dialog appear on the desktop; Cancel gives "Not authorized". polkit only reads actions from `/usr/share/polkit-1/actions`, so our own `org.sios.owner` action ships in the image and can only be tried after an image build.
- 2026-10-14 (M4): Built the model gateway in capd (`src/gateway/`: keys sealed with ChaCha20-Poly1305 under a master key that `systemd-creds --user` seals on the VM, `master.cred`; providers Anthropic with structured outputs and server-side fallback, OpenAI Responses, OpenAI-compatible with a JSON-mode fallback, Gemini native), brain-d's `BrokerModel` (no key, `RestrictAddressFamilies=AF_UNIX`, the goal's pass sent along so Sensitive data stays local), and Settings > Brain (`broker.cpp`, async socket requests, `PR_SET_DUMPABLE 0`). Tests: capd 82, brain-d 10. Seen on the VM: the page lists the five providers live from the broker. polkit refuses details from unprivileged callers ("Only trusted callers ... can use CheckAuthorization() and pass details"), so the dialog can't name the exact request; instead three actions with their own wording, and the dialog tells the owner to confirm only what they just did. The first image with the Rust stage failed: on atomic bases `/root` links into `/var`, so the cargo cache mount failed; `CARGO_HOME=/cargo` fixes it. Docker on the Mac can't load the Kinoite base ("max depth exceeded"), so the image build on GitHub (podman) is the only full check. Copying over a running binary on the VM failed silently; `build-rust.sh` now copies beside and renames. Gemini native and OpenAI-compatible are untested without keys.
- 2026-10-14 (M5): `sios-approve` is woken by capd over the session bus (`org.sios.Approve1.Show`, no data) and asks the broker `pending.list` itself. Seen on the VM against a test broker: a waiting email from "claude-code (a connected app)" with its recipient, subject, body, attachment, risk chips and reason, and a waiting tidy pass with its folder, time limit and action count. Deny removed it (`decline ok`). Allow goes through the owner's password, so it can only be checked once the image has the polkit actions. Because yes always needs the password, an AI pressing Allow through accessibility (12-risks) only gets a password dialog it can't answer. After a security review, only SIOS's own window apps (known by program: `sios-approve`, `sios-settings`) may list waiting requests or decline them; other programs can't read other AIs' goals or email bodies. Program identity is enough to look and to say no, never to say yes.

Checked on the VM through a test broker with real adapters: volume 40 to 25 (`wpctl`), brightness 100 to 50 (`busctl` to `org.kde.ScreenBrightness/display0`; the VM's display is adjustable), wallpaper Dusk to Lake, a notification shown, Files opened on a folder (`kioclient`), Settings opened (`kstart`), `system.state` and `network.list` read; one `undo` of the goal put volume, brightness and wallpaper back. - 2026-10-14 (M7): The Ask bar offers "Ask SIOS" first and follows the goal in the bar. brain-d treats the Ask bar (known by program) as the owner's shell for starting goals only; brain-d's owner controls stay off on the image. Not checked end to end yet (brain-d must run from `/usr/bin` to be the broker's service). - 2026-10-14 (M1): Tools renamed in capd, brain-d, the harness and the preview (one scripted swap of exact names, then prefix patterns like `fs.*` by hand). Old names stay accepted through `tools::ALIASES`: `manifest::canonical()` maps them on calls, and passes, standing rules (`rules.json`) and saved roles (`iam.json`) are rewritten on load, so the owner's existing files keep working. An old area pattern becomes exactly the new names its tools moved to (`sys.*` never grows to cover installs). Area names must never contain `_`, because wire names split at the first `_`; a test enforces it. `apps.close` is now a change, not a read (unsaved work). capd 75 tests and brain-d 8 tests pass; the live run with GPT passed summarize, tidy and email (approved) with the audit chain intact. The harness goals pointed at files the seed no longer has (`Q3 board notes.txt`, `Projects/README.md`); fixed to the seed's names. The preview's browser confusion test was not rerun; it type-checks and lints clean. Catalog written up in `docs/plan/16-tool-catalog.md`.
- 2026-10-15 (A7): Suggestion cards are plain rules over names, counts and times; the headline is written by SIOS and "Do it" starts a normal goal, so the plan review still applies (D57, D70). The review found that anything able to reach the Ask bar's D-Bus name could press "Do it" for the owner (now an outside request only opens the bar on the card) and that anyone could turn a kind off for good by dismissing it three times (now only the owner's surfaces count). Look then plan (D72): the planner may ask for up to 3 files.find or files.list lookups, run under their own small read-only pass, then plans once more with the results labelled as data. files.list answers with "items", not "entries". The review then found that names from disk went to the planner as raw text, so a file named with line breaks and a fake REQUEST could read like instructions: each found path is now one quoted string with control and direction characters removed, and a plan made after a look can't include mail.send. A later review of A5 found that capd wrote the agent's MCP config inside the home the agent can change, so the agent could plant a link there and have capd overwrite one of the owner's files: the config now lives in the agent's owner-only folder, is written with create_new (never follows a link) and is bound into the sandbox read-only. The next review found the same gap on the two other re-plans (after the broker refuses a plan, and after a step fails partway), which pass error text and done steps that can carry names from disk: every re-plan now quotes that text, and once disk text has reached the planner, no later plan in that goal may include mail.send (one no_send helper in code). A third review found the guard still went by a tool name and that re-plans skipped the filter on one-click actions: every plan now keeps only the safe one-click actions (filtered inside the planner call), and once disk text has reached the planner the pass itself is asked for with no_egress, so the broker refuses any sending whatever the tool is called. A fourth pass: the re-plan after a broker refusal now also counts as disk text. Known limit: the first plan's briefing has always listed file names, so the no-sending guard can't cover it; there the backstop is the broker, where sending is Irreversible and always asks the owner (password, D56), and reading untrusted contents taints the goal.
- 2026-10-15 (C1 reviews): A connector call taints the goal before the service is asked (its errors are its own words, quoted). A connector "read" still sends the AI's words out, so once a goal has read anything on this computer each connector call asks. A service's answer only goes in the reply, never into another step's arguments, and nothing found or written here is filled into a connector's arguments: what goes out is what the owner saw in the plan. Taint from a look's pass doesn't carry to the main pass in capd (separate sessions); brain-d covers it by asking for the main pass with no_egress after any look, and capd enforces that flag. The catalog key's private half is connectors.key on the owner's Mac (git-ignored, like cosign.key): back it up; losing it means a new key and a new image. GitHub's hosted MCP server has a read-only address (/mcp/readonly) and takes a personal access token as a Bearer header. A connector call still holds capd's lock while it waits on the network (up to 30 s per request): it moves off the lock before mail lands (C2).
- 2026-10-15 (A8, D1): The broker counts an agent's tokens from Claude Code's stream-json (input, output and cache writes; each message id once; cache reads are cheap and not counted). The security review of the first version found: the lease left to the broker alone (a broker crash let a run go on; now a systemd timer beside the run stops it, and +1 hour replaces the timer because a running unit's RuntimeMaxSec can't be changed: checked on the VM), a tail window an agent could push its usage out of by writing into its own output (now the stream is read from its start, up to 32 MB, past which the run stops, and counts never go down), the stream read every 3 s under the broker's lock (now read outside it), unknown runs not stopping, the sign-in sandbox losing its 30-minute ceiling, and unit names an agent's name could collide with. Konsole 26.08 follows light and dark itself: [LightDarkTheme] SyncProfileWithSystemTheme with profile names (not file names); its toolbars live in UI files compiled into the program, so SIOS ships copies without them at a higher version. QML Text guesses rich text by default: anything showing names from disk or text from an AI or service needs textFormat: Text.PlainText, or a file name can style itself, add links or load an image from the network.
- 2026-10-16 (L0): The planner couldn't see six tools (mkdir, restore, delete, apps.list, network.list, system.state); it can now, but only files.find, connector answers and compose output can feed later steps until plan v2. apps.close and system.lock stay Reversible: closing goes through the app's own "save changes?" and locking ends when the owner unlocks, so neither loses data. The undo journal is saved to undo.json (owner-only, newest 500) and read back only if every path stays inside the home and SIOS's snapshots and adapter undos are the known ones, so an edited file can't aim "undo" at /etc or another program. The image build compiles brain-d without the llm folder, so prompts stay in code and a test compares them to llm/prompts (skipped when the folder is absent). The sample briefing doesn't list the hidden Trash, so Trash examples look there first instead of guessing paths.
- 2026-10-16 (L2): The image has 2,343 programs: 1,870 have a man page, 451 more answer --help (run in bwrap with no network and a read-only root; on Fedora Atomic /home and /root are links, so the sandbox hides /var/home and /var/roothome instead), 22 have neither. man output carries colour codes (groff SGR) unless stripped. The sandbox is the real guarantee, not the class: a "read" runs with read-only folders and only loopback networking, so a sed script that tries to write a file got "Read-only file system" on the VM. Folder names with spaces or colons can't be given to systemd as bind paths yet, so such folders aren't visible to commands. The broker trusts only the image's own brain-d, so a brain built for testing can't drive the broker (as intended): broker features are tested with a separate test broker in secret-file mode. A command a paired app runs after the owner approves it through sios_approval_status returns its start, not its output, until that tool collects results too.
